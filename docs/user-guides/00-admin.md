# Администратор — полное руководство

Админ настраивает систему и может всё, что разрешено другим ролям, плюс каталог, пользователи, SLA и прыжки статусов.

**Меню:** Главная · Заказы · Новый заказ · Очередь · Задачи · Клиенты · Отчёты · Каталог · Админка · Справка

---

## Ограничения других ролей (сводка)

| Роль | Видит заказы | Создаёт | Правит поля заказа | Статусы | Отмена / удаление | Файлы | Задачи | Отчёты | Каталог / админка |
|------|--------------|---------|--------------------|---------|-------------------|-------|--------|--------|-------------------|
| **Фотоцентр** | Только своя точка | Да | Только свои, статус «Новая» (+ причина) | Нет | По умолчанию нет (флаги) | Блок «точка» | Да | Нет никогда | Нет |
| **Производство** | Все | Да | Только `source=production` | До «Готов к выдаче» | Да | Догрузка блока «точка» | Да | С флагом | Нет |
| **Дизайнер** | Все | Нет | Нет | До «Готов к выдаче» | Нет никогда | Блок «дизайнер» | Да | С флагом | Нет |
| **Курьер** | Только выдача | Нет | Нет | Готов ↔ У курьера → Выдан | Нет | Нет | Нет | Нет никогда | Нет |

### Флаги прав (Админка → пользователь)

- **Выдать:** отчёты / смена цены / отмена / soft-delete / управление SLA.
- **Снять (deny):** отобрать право, которое роль даёт сама (например, отмену у производства).
- Дизайнеру **нельзя** выдать отмену/удаление — система игнорирует.
- Фотоцентру и курьеру **нельзя** открыть отчёты флагом.

### Статусы заказа

Новая → Принят → У дизайнера → На производстве → Готов к выдаче → У курьера → Выдан. Отдельно: Отменён.

| Кто | Статусы |
|-----|---------|
| Фотоцентр | Не двигает |
| Производство / дизайнер | ←/→ до «Готов к выдаче» |
| Курьер | Готов ↔ У курьера → Выдан |
| **Админ** | ←/→ и модал **«Перейти в…»** в любой статус |

## Главная (`/dashboard`)

Обзор текущего месяца и быстрые ссылки.

**Что видите:** KPI (заказы, выручка, средний чек, % выданных) за **текущий календарный месяц**; счётчики статусов; срочные; SLA просрочки; очередь цеха; задачи; последние заказы.

**Пример:** утром открываете Главную — видите, сколько заказов за сентябрь и есть ли просрочки SLA.

---

## Заказы (`/orders`)

Список всех заказов (кроме soft-deleted по умолчанию).

### Как пользоваться

1. Поиск по номеру / клиенту.
2. Фильтр статусов (можно несколько), период дат.
3. Раскрыть строку ▶ — состав позиций.
4. Галочка **ТТН** (admin/production).
5. «Срочно» — флаг срочности.
6. Админ: ☑ «Показать удалённые».

### Когда можно / нельзя править заказ

Откройте карточку заказа (`/orders/[id]`).

| Действие | Когда можно | Когда нельзя |
|----------|-------------|--------------|
| Поля заказа, состав, цены | Всегда (кроме отменённого / удалённого) | `cancelled` или soft-delete |
| Статусы ←/→ | По графу переходов | Нет допустимого соседа |
| «Перейти в…» | Всегда (админ) | — |
| Отмена | С причиной | Уже отменён / удалён |
| Soft-delete | Свой пароль + комментарий | Уже удалён |
| Файлы обоих блоков | Да | Удалённый заказ |
| Аудит цен | Да (admin + production) | — |

**Пример:** заказ точки в статусе «На производстве» — админ может править состав и прыгнуть сразу в «Готов к выдаче».

**Отмена ≠ удаление:** отмена — статус с причиной (виден в воронке). Удаление — скрытие из списков (пароль); оба вне KPI.

## Новый заказ (`/orders/new`)

1. Выберите клиента (точка сети или внешний).
2. Позиции: каталог (категория → подкатегория → товар → qty) или ☑ «Ручная позиция» (название + цена вручную).
3. «Для курьера», срочность — по необходимости.
4. Сохранить → номер `DK-ГГММДД-N`.

**Правила цены**

- Из каталога: цена **с сервера** (снимок). Правка прайса позже **не** меняет старые заказы.
- Ручная: цена, которую ввели при создании.
- Категория тоже фиксируется снимком (`Полиграфия / Визитки`) для карточки, Telegram и отчётов.

**Пример:** импортировали новый прайс — вчерашний заказ остаётся со старой ценой; новый заказ возьмёт новую.

## Очередь (`/workshop`)

Компактная очередь цеха: статусы от «Принят» до «Готов к выдаче» (без «Новая»).

- Кнопки ←/→ в строке.
- Раскрытие состава: позиция, qty, техпараметры, «макет: есть/нет».
- Список обновляется периодически.

**Пример:** дизайнер и производство смотрят одну очередь; админ может вмешаться статусом с карточки.

## Задачи (`/tasks`)

| Вкладка | Смысл |
|---------|--------|
| Мои | Назначены вам |
| Поставленные | Создали вы |
| Все | Мои ∪ поставленные (**не** все задачи компании) |

Поля: название, описание, исполнитель, заказ (необязательно), приоритет, срок, статус (open → in_progress → done / cancelled).

**Пример:** «Сверстать визитки DK-260902-3» → назначить дизайнера → привязать заказ.

## Клиенты (`/clients`)

- **Точка сети** — создаётся вместе с пользователем photo_center; soft-delete **запрещён**.
- **Внешний клиент** — без логина; админ может soft-delete (комментарий).
- Карточка: данные + история заказов (без удалённых по умолчанию).
- Админ: «Показать удалённых».

**Пример:** разовый юрклиент больше не нужен → soft-delete; старые заказы остаются привязаны.

---

## Отчёты (`/reports`)

Период (по умолчанию месяц), KPI, воронка (+ колонка «Отменён»), по клиентам, по категориям, SLA, задачи, % ТТН, экспорт CSV/Excel, печать.

**В KPI не входят:** отменённые и soft-deleted.

**Пример:** «По категориям» берёт снимок категории с позиции заказа, а не текущее имя в каталоге.

## Каталог (`/admin/catalog`) — подробно

Только **admin**. Здесь прайс: дерево категорий, позиции, цены, импорт/экспорт, расходники (BOM, задел под склад).

### Структура

1. **Корень** (например «Полиграфия»).
2. **Подкатегория / лист** (например «Визитки») — товар создаётся **только в конечной** категории (leaf).
3. **Позиция** — название, цена, код `external_code` (из 1С / прайса).

### Ручное редактирование

| Действие | Как | Ограничения |
|----------|-----|-------------|
| Создать категорию / подкатегорию | Форма в дереве | Имена обязательны |
| Создать / править товар | Выбрать leaf → форма | Цена через деньги сервера; не создавать на корне с детьми |
| Деактивировать | Предпочтительнее удаления | Старые заказы не ломаются |
| BOM / расходники | В карточке товара | UI минимальный; списание со склада — не в v1 |

**Пример:** переименовали «Визитки» в «Визитки 90×50» — уже созданные заказы в карточке/TG/отчётах сохраняют **старый** путь категории (снимок).

### Экспорт

Кнопка **Экспорт** → xlsx в формате CRM (колонки A–G). Позиции без кода уходят как `crm:{uuid}` для повторного импорта.

### Импорт: общий сценарий

1. Выбрать файл `.xlsx` (до 10 МБ).
2. Откроется **preview** (без записи в БД): формат, число строк, предупреждения, образец.
3. При необходимости ☑ **«Заменить цены»**.
4. Подтвердить импорт.
5. Есть лимит частоты импортов (не спамить подряд).

**Автоопределение формата (`source=auto`):**

| Формат | Когда | Что это |
|--------|-------|---------|
| **CRM / 1С** | Один лист, колонки A–G | Базовый формат v1 |
| **Прайс ФЦ** | Несколько листов-матриц (Фотопечать, Полиграфия, …) | Commercial add-on |

### Базовый формат 1С / CRM (колонки)

| Col | Заголовок | Назначение |
|-----|-----------|------------|
| A | category_code | Код корня (необяз.) |
| B | category_name | Имя корня |
| C | subcategory_code | Код подкатегории |
| D | subcategory_name | Имя подкатегории |
| E | product_code | **Ключ совпадения** (SKU) |
| F | product_name | Название |
| G | unit_price | Цена |

Русские алиасы заголовков тоже принимаются.

### Правила импорта (важно)

| Ситуация | Поведение |
|----------|-----------|
| `product_code` уже есть | Поля **не** затираются |
| Есть код + ☑ «Заменить цены» | Обновляется **только** `unit_price` |
| Кода нет в БД | Создаются категория / подкатегория / товар |
| Товар на non-leaf | Ошибка / предупреждение (leaf-policy) |
| Повтор без кодов категорий | Могут появиться дубли категорий — лучше всегда слать коды из 1С |

**Пример «догрузка»:** выгрузили экспорт → добавили 20 новых строк с новыми `product_code` → импорт **без** «Заменить цены» → старые цены и имена не тронуты, новые позиции созданы.

**Пример «обновить прайс»:** тот же файл с новыми ценами + ☑ «Заменить цены» → совпавшие по коду позиции получили новые цены; названия не менялись.

### Парсинг «Прайс ФЦ» (add-on)

Файл вида «Прайс ФЦ ДД.ММ.ГГГГ.xlsx» с листами (Фотопечать, Распечатка, Сувенирка, Полиграфия, …).

1. Загрузите файл как обычно — preview покажет формат **«Прайс ФЦ (multi-sheet)»**.
2. Парсер разбирает матрицы листов в плоские строки (категория / подкатегория / имя / цена).
3. Дальше те же правила match по коду и «Заменить цены».
4. Это **опциональная** функция (коммерческий add-on); базовый путь приёмки — формат 1С A–G.

**Пример:** прислали прайс ФЦ на 1 сентября → preview → проверить warnings → импорт с «Заменить цены».

### Чего каталог не делает

- Не пересчитывает уже созданные заказы.
- Не списывает склад (BOM только задел).
- Не доступен ролям кроме admin.

## Админка

### Пользователи (`/admin/users`)

- Создать / править: email, имя, роль, пароль, для photo_center — название точки.
- Флаги grant и deny; в форме видны **эффективные** права.
- Деактивация `is_active` (не удалить последнего admin).
- Смена роли photo_center → другая: связь с клиентом-точкой не ломать без явного решения.

**Пример:** выдать production доступ к отчётам → флаг «Отчёты».

### SLA (`/admin/sla`)

- Цели SLA (по умолчанию 72 ч).
- Системную default-цель нельзя удалить как обычную.
- Просрочки → push / Telegram (cron; на Hobby — раз в сутки).

---

## Справка (`/help`)

Показывает **это** руководство (только для роли admin). Другие роли видят свой файл — подменить роль через URL нельзя.

---

## Кейсы админа (кратко)

1. **Точка сети** — Пользователи → photo_center + имя точки.
2. **Внешний клиент** — Клиенты → создать; при необходимости soft-delete.
3. **Флаг отмены точке** — пользователь → can_cancel_order.
4. **Deny отмены production** — deny_cancel_order.
5. **Прыжок статуса** — карточка → «Перейти в…».
6. **Импорт прайса** — Каталог → файл → preview → заменить цены? → импорт.
7. **Отчёты месяца** — Отчёты → KPI / экспорт.
8. **Soft-delete заказа** — пароль + комментарий; «Показать удалённые» в списке.
